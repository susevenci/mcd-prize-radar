## 实测发现的接口形态（与文档不一致之处）

1. **响应统一带信封**：实际返回是 `{"success":true,"code":200,"message":..,"datetime":..,
   "traceId":..,"data":<业务数据>}`，且 `structuredContent` 与 `content[0].text`
   会同时给出（text 里还附带一段人类可读的字段说明）。不拆 `data` 外壳就会误判"返回为空"。
   本项目在 `src/mcp_client.py::_unwrap_envelope` 统一处理。
2. **`list-nutrition-foods` 的 `data` 是字符串而不是数组**：形如
   `[160]{productName,nutritionDescription,energyKj,energyKcal,protein,fat,carbohydrate,sodium,calcium}:`
   随后每行一条逗号分隔记录，`null` 表示无值。`nutrition.parse_pseudo_table()` 负责解析。
3. **营养维度不含「糖」**：160 款里 `sugar` 字段全部缺失，因此项目对糖维度一律标"数据缺失"，
   绝不按 0 参与判定。
4. **能量同时给 kJ 与 kcal 两列**：按 kJ 列换算（÷4.184），并有"异常大值按 kJ 处理"的兜底。
